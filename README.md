# Topology-driven BIM-to-BEM for occupancy-based energy scenario analysis

Code, models and data of the paper

> A. Massafra, R. Villa, G. Salvalai, R. Gulli, M. D'Orazio. *Topology-Driven BIM-to-BEM for
> Occupancy-Based Energy Scenario Analysis in Higher-Education Buildings* (submitted).

The workflow generates space-oriented Topological BIMs (TBIM) of existing higher-education
buildings, converts them into EnergyPlus models (BIM-to-BEM), tunes the models against monitored
indoor temperatures, simulates twelve occupancy-management scenarios, integrates models and KPIs
in a knowledge graph and visualises them in a decision-support dashboard. The case study is
Buildings 09 and 10 of the Lecco Campus of Politecnico di Milano.

Developed within the PRIN 2022 project **DIGITMAN** – *Occupant-based DIGITal predictive MANagement
to improve the built environment* (ID 2022JMRX2A), funded by the European Union – Next Generation EU,
Mission 4 Component 1, CUP D53D23003630006.

## Workflow and paper sections

| Step | Script / notebook | Paper | Main outputs |
|---|---|---|---|
| BIM-to-BEM conversion | `01_bim_to_bem` | §3.2.2, Fig. 1–2 | TBIM with thermal zones, baseline BEM (IDF) |
| BEM tuning | `02_bem_calibration` | §3.3.1, §4.2, Table 3, Fig. 7–9 | tuned BEM, error metrics, monthly comparison |
| Energy analysis of the tuned BEM | `03_baseline_analysis` | §4.2 | annual and monthly energy needs, zone maps |
| Scenario modelling | `04_scenario_modelling` | §3.3.2 | 12 scenario BEMs × 2 buildings |
| Scenario simulation | `05_scenario_simulation` | §3.3.3 | EnergyPlus results (not versioned) |
| Scenario KPIs | `06_scenario_kpis` | §3.3.3, §4.3, Table 5 | `scenario_kpis.csv`, summary table, zone totals |
| Sensitivity analysis | `07_sensitivity_analysis` | §4.3, Fig. 10 | sensitivity KPIs and tornado values |
| Knowledge graph | `08_knowledge_graph` | §3.4, Fig. 3–4 | JSON-LD graph (optionally written to Neo4j) |
| Dashboard (DSS) | `app/app.py` | §3.5, Fig. 5 | Dash web application |
| Paper figures | `scripts/figures/fig_*.py` | Fig. 2, 7–10 | `figures/*.png|pdf|svg` |

Each step is available both as a Python script (`scripts/`) and as a Jupyter notebook
(`notebooks/`) with the same content: the notebooks are generated from the scripts with
[Jupytext](https://jupytext.readthedocs.io) (percent format) and can be re-synchronised with
`jupytext --sync notebooks/*.ipynb`.

## Installation

1. **Python 3.11** and the packages of `requirements.txt`:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate          # Windows (source .venv/bin/activate on Linux/macOS)
   pip install -r requirements.txt
   ```
2. **EnergyPlus 24.2** ([energyplus.net](https://energyplus.net/downloads)). The default installation
   folder is `C:\EnergyPlusV24-2-0`; otherwise set `ENERGYPLUS_DIR` in a `.env` file (see `.env.example`).
   The BEMs are written for EnergyPlus 24.1, as in the paper, and converted to 24.2 with the
   transition program shipped with EnergyPlus 24.2.
3. *(Optional)* a Neo4j database, to which `08_knowledge_graph` writes the knowledge graph when
   run with `--neo4j yes` (or when answering *y* to its prompt). The connection URI, username and
   password are asked at run time and are not stored.

## Usage

Run the steps from the repository root (or open the notebooks in `notebooks/`):

```bash
python scripts/01_bim_to_bem.py --building building10        # and --building building09
python scripts/02_bem_calibration.py --building building10   # and building09
python scripts/03_baseline_analysis.py --building building10 # and building09
python scripts/04_scenario_modelling.py
python scripts/05_scenario_simulation.py --workers 6         # 24 annual simulations
python scripts/06_scenario_kpis.py
python scripts/07_sensitivity_analysis.py
python scripts/08_knowledge_graph.py
python app/app.py                                            # dashboard at http://127.0.0.1:8050
```

Figures: `cd scripts/figures` and run `python fig_<name>.py`.

Steps 02–08 start by default from the models archived in `models/`, i.e. the models used for the
paper, so that the results do not depend on the software versions used for the BIM-to-BEM
conversion. Use `--baseline regenerated` (02) and `--calibrated results` (04) to chain the steps
on the models regenerated by 01 and 02. The dashboard needs only the versioned results
(`results/knowledge_graph/`, `results/scenarios/zone_annual_totals.csv`, `models/`).

The 24 scenario simulations take about 20 minutes on a 22-core workstation (6 parallel runs).
The dashboard needs about 2 minutes to start (loading of the TBIMs); the 3D view is then updated
in 2–7 seconds.

## Reproducibility

The refactored pipeline was checked against the original models and results:

| Check | Result |
|---|---|
| `01` thermal zoning vs TBIM with zones of the paper | identical cells → zones assignment and zone names |
| `01` BEM vs `models/<building>_bem_baseline.idf` | identical zones, schedules, constructions, loads, external envelope and shading; internal (interzone) surfaces differ in vertex order and surface type, a TopologicPy/Honeybee version effect |
| `02` tuned BEM vs `models/<building>_bem_calibrated.idf` | identical (Building 09: two internal surfaces with a different name) |
| `02` pre-tuning metrics vs Table 3 | Building 09 identical; Building 10 identical in the winter and autumn weeks, small differences elsewhere (EnergyPlus 24.2 instead of 24.1) |
| `04` scenario BEMs vs the original scenario models | identical (24/24) |
| `06` scenario KPIs vs the original scenario KPIs | identical (relative difference 0 for all end uses and KPIs) |
| `07` sensitivity (tornado) values vs the original values | identical |

Notes:
* **scikit-learn 1.2.2** is required to reproduce the thermal zoning: later versions return the
  same clusters with a different numbering, and hence different zone names.
* The tuning metrics (Table 3) compare the sensor readings with the simulated **Zone Mean Radiant
  Temperature** of the classroom zone and define MTDW as *measured − simulated*.
* The tuned BEMs in `models/` are those of the first (manual) tuning, which feed the scenario
  analysis of this repository. The full-year RMSE of the tuned models is 2.11 °C (Building 10) and
  2.91 °C (Building 09).
* The KPI definitions (heating and cooling as ideal-load supply-air energy, ventilation fan
  electricity from the AHU rated power, conversion factors) are implemented once in
  `digitmanpy.Operation.KPI` and shared by steps 03, 06, 07 and 08.

## Data

The input data describe two buildings of the Lecco Campus of Politecnico di Milano: TBIMs derived
from the architectural CAD drawings and space inventory, construction properties from technical
sheets, HVAC schedules and AHU electrical power, occupancy schedules from the university booking
service, hourly indoor air temperatures of two monitored classrooms (A1.3, Building 10; B1.5,
Building 09) and the weather data of the on-site station for 2024.

The IFC files were exported from an Italian-language Revit installation: the Revit property sets
and property names (e.g. pset `Altro` = *Other*, property `Nome` = *Name*) and the material names
inherited from the BIM (e.g. *Solaio laterocemento* = hollow-tile concrete slab) are kept as in
the source data, since the workflow uses them as keys. Identifiers such as `EqpSch_Costant` keep
the original spelling of the models for the same reason.
